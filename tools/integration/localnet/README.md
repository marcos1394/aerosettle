# CON-34 Localnet runner

Prerequisites: Solana CLI/test-validator 4.1.2, Rust 1.89, Node 24, Python 3.12+, `npm ci --prefix tools/bootstrap`, `pip install -r requirements.txt`, and `cargo build-sbf --manifest-path programs/aerosettle/Cargo.toml`. No production wallet is read. The runner uses only fresh in-memory test keypairs and test SPL mint; it stores public evidence and an isolated SQLite database in a new temporary directory.

Run `bash tools/integration/localnet/run_localnet_e2e.sh`. The script starts a validator on loopback RPC port 18899 with a separate faucet on 18909, deploys `target/deploy/aerosettle.so` at genesis, executes five scenarios, reconstructs receipts using actual JSON-RPC, tests immediate/concurrent/SQLite replays, stops and restarts the **same** ledger without reset, then requires that genesis, signatures, blocks, WorkOrder accounts and SPL balances remain available. It compares evidence hashes and SQLite effect IDs across the restart. It exits nonzero if any check fails and does not delete its ledger. It requires at least 3 GiB free for the complete matrix (1 GiB for `CON34_SCENARIOS=full`) and uses 48 ticks per slot to reduce ledger growth while retaining sufficient blockhash lifetime for transaction submission; this changes block production cadence, not transaction validation or finality. `CON34_RPC_PORT` and `CON34_FAUCET_PORT` select unused ports. Set `CON34_PUBLIC_REPORT_DIR` to copy only public JSON reports and before/after RPC diagnostics for CI; never upload the ledger or keypairs.

`CON34_SCENARIOS=full` runs just the full payout when storage is constrained, while the default runs full, zero, proportional, invalid shared and valid shared. A one-scenario run proves only that case. The GitHub Actions workflow uses the complete matrix, a pinned Agave release with SHA-256 check, and uploads only public JSON after a successful run. It runs on updates to the CON-34 PR; manual dispatch will also be available once the workflow exists on the default branch. PR and master regressions run separately in `con34-regression.yml`.

The web regression job copies the tracked IDL and the explicit Localnet evidence requirement mask into ignored build inputs. This makes a clean checkout reproducible without treating the mask as transaction or attestation proof.

The prior `getTransaction: null` observation came from a ledger that had hit `No space left on device` in RocksDB; its transaction status service stopped, and offline blockstore bounds no longer included the settlement slot. A clean one-scenario restart recovered `getTransaction`, historical status, block membership, account data and balances on the same genesis. The complete five-scenario matrix also passed locally with four historical RPC recoveries after two restarts; the PR workflow remains the final remote gate. Reports from unavailable ledgers remain `HISTORICAL_FIXTURE`, never current `LIVE_RPC`.
